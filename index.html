2nr API Documentation

Complete reverse-engineered documentation of the 2nr (also known as drugi-numer) virtual number & SIP softphone service. All information is derived from real network traffic captures (HAR files) of the official Android application pl.rs.sip.softphone.newapp version 2.1.18-prod.

Base URL
https://api.2nr.xyz
Protocol
HTTP/2 + Cookie Auth
App Package
pl.rs.sip.softphone.newapp

Architecture

The API uses an unusual design: almost every request is a POST to a service path, and the actual operation is identified by a numeric action ID inside the JSON body.

// Typical request shape
POST /numbers/reserveNumber HTTP/2
Host: api.2nr.xyz
Cookie: token=<session_token>; x-app-version=52
Content-Type: application/json

{
  "query": { ...parameters... },
  "id": 301          // ← Action ID
}

The full mapping of action IDs is returned by the GET /config endpoint on app startup.

Authentication

Authentication is cookie-based. After successful login or registration the server sets a long hex session token.

Cookie
token=<64-char hex>; x-app-version=52

Login (Action 101)

{
  "email": "user@example.com",
  "password": "ComplexPass1!",
  "imei": null,
  "main_number": "...",
  "language": "en"
}

Password Rules

  • Minimum 6 characters
  • Must contain uppercase letter
  • Must contain lowercase letter
  • Must contain digit
  • Must contain special character: ?!@#$%^&*()<>+{}|_-

Numbers API

Reserve Number (301)

This is the core endpoint. Requires a valid Play Integrity / device attestation token.

{
  "query": {
    "availability_days": [1,2,3,4,5,6,7],
    "color": "#E63147",
    "hour_from": null,
    "hour_to": null,
    "integrity_token": "<JWE Play Integrity token>",
    "marketing": true,
    "name": "MyNumber",
    "nonce": "base64-nonce",
    "number_id": 147446
  },
  "id": 301
}

Successful response:

{
  "success": true,
  "password": "a412471c2c86f5cf95c987106dc6ee0bda99643ad18d1f5c5fa28e08550a95b2"
}

Get User Numbers (302)

{
  "id": 302
}

Returns array of owned numbers with reservation window (typically 3 days), color, name, and the password hash.

Remove Number (304)

{
  "query": { "number_id": 20987 },
  "id": 304
}

Security Notes

  • Play Integrity required – Number reservation demands a valid device attestation token. Emulators or rooted devices are likely blocked.
  • Firebase blocked – The official Firebase API key returns API_KEY_ANDROID_APP_BLOCKED for this package.
  • Session tokens are long-lived hex strings. Protect them carefully.
  • Number passwords are returned as SHA-like hashes and appear to be the SIP credentials.
  • Heavy Facebook App Events tracking is present for analytics.

Observed User Flows

New Account + First Number

  1. App start → Facebook events + Crashlytics
  2. Register / Login → receive session token
  3. getUserDetails (203)
  4. reserveNumber (301) with integrity token
  5. getUserNumbers (302) → number appears (3-day window)
  6. Poll SMS endpoints

Receive Verification SMS

  1. Poll getUnreadMessageCount (411)
  2. Call sms/get (400 or 409)
  3. Extract code from message body
  4. markAsRead (410)
